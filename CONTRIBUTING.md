# Contributing

Thanks for contributing.

## Development

1. Fork the repository.
2. Create a feature branch from `main`.
3. Create a virtual environment.
4. Install `requirements.txt`.
5. Run `pytest`.
6. Make focused changes.
7. Update documentation when behavior or configuration changes.
8. Open a pull request against `main`.

## Pull requests

A good pull request should:

- Explain what changed and why.
- Keep unrelated changes out.
- Include tests for behavioral changes.
- Update documentation for user-facing changes.
- Avoid secrets and customer data.
- Pass the GitHub Actions checks.

## Code style

Keep Python straightforward and typed where practical. Prefer small functions and explicit configuration over hidden global behavior.

## Security

Do not report vulnerabilities in public issues. Follow [SECURITY.md](SECURITY.md).
