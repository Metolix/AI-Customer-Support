# Security Policy

## Supported versions

Security fixes are made against the current `main` branch and the latest published release.

## Reporting a vulnerability

Please do not disclose security vulnerabilities through a public GitHub issue.

Use GitHub's private vulnerability reporting feature if it is enabled for this repository. If that option is unavailable, contact the repository owner privately through GitHub.

Include:

- A clear description of the issue.
- Reproduction steps or a proof of concept.
- The affected file or endpoint.
- Potential impact.
- Any suggested mitigation.

Please do not include real API keys, customer data, passwords, or other secrets in a report.

## Scope

Relevant examples include:

- API key or credential exposure
- Authentication or authorization bypass
- Prompt-injection paths that cross application trust boundaries
- Data leakage
- CORS or server configuration vulnerabilities
- Remote code execution
- Dependency vulnerabilities with a practical impact
